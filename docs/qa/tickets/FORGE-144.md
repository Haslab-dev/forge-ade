# FORGE-144 — Agent turn ends silently empty when the provider drops tool calls

- **Type:** Bug · **Priority:** High · **Status:** ✅ Fixed (primary root cause) · **Component:** agent/harness
- **Labels:** `gui-verified`, `live-agent-round`, `provider-interaction`
- **Found in:** Computer Use live round on General workspace, model deepseek-v4-1-flash then mimo-v2-6-flash (both via the "Kenari" OpenAI-compatible proxy).
- **Evidence:** two consecutive prompts requiring tool calls ("start a background task", "run echo TOOLTEST-123") ended with **completely empty assistant messages** — no tool block, no text, no error, no retry affordance. On mimo the turn produced a "Worked for 2s" block containing only a Thought in which the model itself states: *"my tool calls were malformed — I see \"update_tasks\" and \"echo …\" as raw content instead of proper tool invocations"*. Another turn rendered the in-band tool syntax verbatim to the user (`<function=updatetasks>[…]</function>` as plain message text). No `/tmp/forge-ade-task-*` artifacts were created; no error was surfaced to the UI or the log.
- **Root cause (confirmed via server log after adding a per-turn tool-count diagnostic):** the frontend `sendGoAgentMessage` **30s liveness watchdog** killed the Go harness turn whenever the provider produced no streaming deltas within 30s (routine for reasoning models / slow tool-call generation — the server log shows `context canceled` ~90s in), then **re-sent the same prompt through the browser-side fallback** (agentEngine), which had no working provider → "Failed to fetch" / empty bubbles / "(stopped by user)". A second, independent contributor: the Kenari proxy intermittently delivers tool intent as plain text instead of native tool calls.
- **Fix:** removed the kill-and-fallback — the Go harness owns the turn end-to-end and surfaces its own errors; the liveness check now only logs after 120s. Frontend suite green. A per-turn `[agent:<id>] turn N: offering M tools` diagnostic log was added (it exposed this root cause and the JEV drop).
- **Remaining (follow-up):** an inline "provider slow — keep waiting?" affordance and empty-turn retry; debug-level logging of raw provider responses for proxy diagnosis.
