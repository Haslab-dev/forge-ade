# FORGE-139 — Side-pane tabs are destroyed by closing the pane (user-found, fixed)

- **Type:** Bug · **Priority:** Medium · **Status:** ✅ Fixed (this cycle) · **Component:** side-panel
- **Labels:** `user-reported`, `gui-verified`, `fixed`
- **Reported by:** repo owner — "when open any feature sub-sidebar, when close sidebar, the tab is closed; it should keep persist unless user close by x button".
- **Root cause:** The side pane holds its tab list (`paneTabs` / `activeTab` / `tabOpen`) in component-local state. Of its four mount sites, only `AgentActiveSessionView` kept the pane mounted (CSS-hidden) when the drawer closed; the other three — `AgentHomeView`, `AgentContainer` (CLI tasks), and `EditorView` — rendered it conditionally (`{isOpen && <AgentRightSidebar/>}`), so closing the drawer **unmounted** the component and destroyed every open tab. Reopening showed the "Choose a tab" chooser again.
- **Fix:** All three conditional sites now use the same keep-mounted + `hidden`-class pattern as `AgentActiveSessionView`, so the pane survives drawer close/reopen on every surface. Tabs are removed only by their X button (`closePaneTab`), whose semantics are unchanged: closing a background tab keeps the selection, closing the active tab selects the last remaining tab, and closing the last tab returns to the chooser.
- **Tests:** new pure module `frontend/src/components/agent/paneTabs.ts` (extracted verbatim from the component, now consumed by it) with 28 unit tests covering the lifecycle edge cases: singleton upsert (no-op/dedupe/immutability), store file-tab mirroring (add/remove/reorder/bail-out/normalization), close activation (background/active/last/none), terminal & conversation title numbering, and terminal focus-by-taskId/reuse rules.
- **Verified in the running app:** agent home — open Git tab → close pane → reopen → Git tab still selected (was: chooser); editor — Git + Side chat tabs → close pane → reopen → both tabs intact (screenshot-verified); close-by-X → chooser returns and stays after close/reopen.
